## 機能候補

優先度の高い順。「規模」は実装からテスト・README 更新までの目安。【要望あり】はユーザーから明示的に要望があった項目。

### 1. 年間表(規模: 中)【要望あり】

- 対象年の 12 か月 × カテゴリのマトリクス表。行がカテゴリ、列が月、右端に年間合計、最下行に月間総支出
- 対象年の切替(← 前年 / 翌年 →)。セルをクリックすると該当月・カテゴリの明細一覧へ
- 月次集計・カテゴリ別集計の CSV / Excel エクスポート(集計は `aggregation.py` を再利用)
- データ構造への影響: なし
- 注意: 内訳(allocations)を使った二重計上防止のルールを年間でも守る。月間総支出は `transactions.amount`、カテゴリ別は内訳を使う
- スマートフォン幅では 12 列の表が収まらないため、月を選んで縦に見る表示か、横スクロールを明示した表にする

### 2. 内訳の一覧表示(規模: 小)【要望あり】

- 明細一覧・ダッシュボードの最近の明細で、内訳のある明細を展開してカテゴリ・金額・メモの内訳行を表示する。今は「内訳」バッジだけで中身は編集画面でしか見えない
- PC のテーブルでは明細行の下に内訳行(インデント付き)、スマートフォンのカードでは折りたたみ(タップで開閉)
- カテゴリで絞り込んだときは、内訳にそのカテゴリを含む明細も一覧に出す(現状は `transactions.category` だけで絞り込んでいる)
- データ構造への影響: なし
- 注意: 合計行は `transactions.amount` を使い、内訳行を足し込まない

### 3. 銀行口座 CSV の取込(売電の入金)(規模: 中)【要望あり】

- 銀行の入出金明細 CSV(1 行目がヘッダー: `日付, 内容, 出金金額(円), 入金金額(円), 残高(円), メモ`。CP932、新しい日付が先)を取り込み、売電の入金(`振込＊トウデンＰＧ コウニユウ`)を収入として記録する
- **重複検知**: 現在の row_key(利用日・正規化した内容・金額・同ファイル内の出現回数)と (row_key, 口座名) の照合をそのまま使えるため、期間を重ねてダウンロードしても重なった行は「重複」として弾かれる。期間指定は不要
- **パーサープロファイル**(候補 7 の第一歩): ヘッダー行の目印を `日付`、金額列を `出金金額` / `入金金額` とするプロファイルを追加し、CSV の内容から自動選択する。`card` にはプロファイル固定の口座名(例: `銀行口座`)を入れる。口座名が変わると重複判定が外れるため固定にする
- **データ構造への影響(要決定)**: 収入を表す `kind` 列(`expense` / `income`)を `transactions` に追加する。金額を負数で持つ案もあるが、ダッシュボードの「総支出」が収入で減って見えるため採らない。旧ファイルは `kind` 空 = `expense` として読む
- **集計**: 総支出は expense のみ。ダッシュボードに「収入」「収支(収入 − 支出)」を追加し、カテゴリ別は expense / income を分けて表示する。年間表(候補 1)でも収入行を分ける
- **分類**: カテゴリに `売電収入` などを追加して使う(カテゴリ画面から追加可)。ルール「トウデンPG コウニユウ → 売電収入」を登録すれば以降は Jev を使わずに確定する。Jev に渡す場合は収入カテゴリも選択肢に入れる
- **出現回数の順序依存**: row_key の出現回数は同ファイル内の行順で数えているため、新しい日付が先のファイルと古い日付が先のファイルで同日同額の行が入れ替わると別扱いになりうる。日付順に並べ替えてから数えるよう `csv_parser` を直す(売電は月 1 回なので実害はないが、汎用化の前提)
- 残高列は取り込まない(必要なら後で `memo` 相当の列に)

### 4. 確信度による絞り込み(規模: 小)【要望あり】

- 明細一覧の絞り込みに確信度(confidence)の条件を追加する。数値入力 1 つと「以上 / 以下」の選択で、`confidence >= X` / `confidence <= X` を指定する
- 値は表示と同じ 0.00〜1.00 の小数で入力する(一覧の確信度列は小数 2 桁表示)。既定は「以下」にしておくと、閾値付近の自動分類をまとめて見直す用途にそのまま使える
- 既存の絞り込み(月・カテゴリ・分類・加盟店)とは AND で組み合わせる。クエリパラメータ(例: `conf=0.80&conf_op=lte`)を追加し、「クリア」で一緒に消える
- confidence が空の明細は数値を入力したとき除外する。ルールで確定した明細も `confidence=None` / `source=rule` なので(`classifier.py` の `ClassificationPipeline.classify`)、除外しないと「以下」の結果に大量に混ざる
- 確信度が空の明細だけを見たい用途のため、「以上 / 以下」に「未設定」を加えた 3 択にする(未設定を選んだときは数値欄を無視する)。rule・manual・分類元が空の旧データが混ざるため、分類の絞り込みでは代替できない
- 不正な入力(数値でない・0〜1 の範囲外)は月の `MONTH_PATTERN` と同じく無視して絞り込みを掛けない
- データ構造への影響: なし(`transactions.confidence` をそのまま使う)
- 実装箇所: `routes.py` の `transactions()` に条件を足し、`templates/transactions.html` の絞り込みフォームに入力欄と `select` を追加する

### 5. 手動明細の追加・削除(規模: 中)

- 現金支出や他カードの支出を画面から登録・削除できるようにする。カード 1 枚分の CSV だけでは家計簿として漏れが出る
- データ構造への影響: `transactions` に列追加は不要。`import_id` は `manual`、`row_key` は空、`classification_source` は `manual` とする。`imports` シートには載せない
- 集計・要確認・ルール適用は既存の明細と同じ扱い。取込の取り消しの対象外(単体削除で消す)
- 画面: 明細一覧に「手動で追加」ボタン、編集画面に「この明細を削除」(手動明細のみ、または取込明細も許可するか要決定)

### 6. 内訳テンプレート(規模: 小)

- KYASH のように毎月分割する明細で、同じ加盟店キーの直近の内訳を「前回の内訳を複写」で埋める
- データ構造への影響: なし(`allocations` から直近の明細を検索して複写)
- 金額が違う月は差額を最後の行に寄せるか、比率で配分するかを選べると便利。まずは差額寄せで十分

### 7. 複数 CSV 形式への対応(規模: 中〜大)

- カード会社ごとのパーサープロファイル(メタ行のキー、ヘッダー行の目印、列名候補、文字コード優先順)を定義し、CSV の内容から自動選択する
- データ構造への影響: `imports` にプロファイル名の列を追加すると追跡しやすい(任意)。`transactions.card` はカード名で区別できる
- 現在の `csv_parser.py` の列名候補タプルを、プロファイルの既定値として切り出す形にすると差分が小さい
- 重複判定は (row_key, カード名) なので別カードの同一明細は別扱いになる。プロファイル間で `card` の表記を揃えること

### 8. バックアップからの復元(規模: 小)

- `data/backup/` の世代一覧を画面に出し、選んだ世代を正本に戻す(戻す前に現在の正本も世代バックアップに退避)
- データ構造への影響: なし
- 注意: 復元中に他のリクエストが保存しないよう、`ExcelRepository.lock` の中で行う

### 9. 明細の単体削除(規模: 小)

- 編集画面から 1 件だけ削除する(内訳も同時に削除)。誤取込や返品の整理用
- データ構造への影響: なし
- 注意: 削除した明細の `row_key` が消えるため、同じ CSV を再取込すると再び新規として入る。削除を「除外」として `row_key` だけ残す設計にするなら `transactions` に `excluded` 列が必要(要検討)

SQL / SQLite、Docker、WSL 前提、n8n、ユーザー認証、外部公開、Dropbox API、Dropbox → Smart Ledger の逆同期、
